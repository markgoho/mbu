{{/* req-dock.html ONE action bar for the whole /requirements/ page, fixed near the bottom of the viewport, that acts on whichever requirement is currently selected and names it by number. It replaces what used to be an always-rendered, opacity:0 action bar on EVERY requirement (see git history for the partial that used to render it, deleted alongside this one's introduction). WHY. That per-requirement bar reserved space even while invisible: below a 40rem req-main container it joined normal flow at ~2.4rem, so roughly a thousand subrequirements on a badge like cooking each carried invisible chrome nobody was looking at -- measured at 4,032px (26%) of the rendered page. A single shared bar means that space is paid for once, if at all, instead of once per requirement. This was chosen over two other prototyped approaches (see git history for the throwaway variant-switcher partial this replaced, whose losing variants were called "Overlay" and "Collapse") which kept per-requirement action bars but tried to avoid reserving space for them positionally. Both still meant up to three buttons' worth of hit-testing and DOM per requirement; the dock needs exactly one set, ever. WHY THIS ISN'T PURE CSS. `.req-main` carries `container-type: inline-size`, which applies layout containment, which makes it a containing block for fixed-position descendants -- so a toolbar that lived inside a requirement could never be promoted to a viewport-fixed dock with plain CSS; it would pin to the bottom of the column instead of the bottom of the screen. That containment is what forces this to be one shared node rendered OUTSIDE .req-main (see the requirements page layout), and a shared node is what forces "which requirement is this acting on" to be scripted rather than resolved per element. deep-link.ts owns that: on focusin/click of any `[data-anchor]` it points this dock at the requirement by setting attributes here -- nothing here is ever built, cloned, or emptied by script; only attributes move. Real controls, authored once, so degraded (no-JS) behaviour comes free.
